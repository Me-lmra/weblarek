# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные

#### Интерфейс IProduct
Содержит в себе данные каждой карточки товара, получаемых с сервера.

#### Интерфейс IBuyer 
Содержит в себе данные покупателя, получаемые из форм и полей ввода.

### Список событий
Взаимодействие слоев Модели (Model) и Представления (View) в приложении. Вся коммуникация между изолированными компонентами осуществляется через Брокер событий (`EventEmitter`).

`catalog:changed` | `Products` — генерируется Моделью каталога, когда в неё успешно загружаются товары с сервера. Сигнализирует Презентеру о том, что нужно взять новый массив товаров и передать его в сеттер компонента `Gallery` для отрисовки на главной странице.
`card:selected` | `Products` — генерируется Моделью каталога при фиксации или сбросе выбранного товара. Сигнализирует Презентеру о необходимости открыть модальное окно детального просмотра (`PreviewCard`) с данными этого товара.
`basket:changed` | `Basket` — генерируется Моделью корзины при любом изменении состава товаров (добавление, удаление, полная очистка). Сигнализирует Презентеру о том, что нужно обновить счётчик в шапке сайта (`Header`), перерисовать список карточек в компоненте корзины (`ModalBasket`) и пересчитать общую стоимость.


### Модели данных 

#### Класс Products
Необходим для хранения списка (массив) товаров, выбранного товара и реализации функционала, связанного с этими товарами, предоставленные для покупки в приложении.

Конструктор:
`constructor(protected events: IEvents)` — принимает объект Брокера событий для уведомления Презентера об изменениях в данных.

Поля класса:  
`private items: IProduct[]` - массив, хранящий список всех доступных в приложении товаров.  
`private selectedItem: IProduct | null` - хранит объект товара, который выбран пользователем для подробного просмотра, или `null`, если просмотр закрыт.

Методы класса:  
`setItems(products: IProduct[]): void` - сохраняет массив товаров, полученный в параметрах, во внутреннее поле класса.  
`getItems(): IProduct[]` - возвращает массив всех товаров, хранящихся в модели.  
`getItemById(id: string): IProduct | undefined` - находит и возвращает один товар из массива по его уникальному идентификатору `id`.  
`setSelectedItem(product: IProduct | null): void` - сохраняет конкретный товар (или `null`) для последующего детального отображения.  
`getSelectedItem(): IProduct | null` - возвращает ранее сохраненный товар для подробного отображения на экране.

#### Класс Basket
Необходим для хранения списка (массив) выбранного товара, который пользователь выбрал для покупки, и реализации функционала, связанного с этим товаром.

Конструктор:
`constructor(protected events: IEvents)` — принимает объект Брокера событий для уведомления Презентера об изменениях в данных.

Поля класса:
`private selectedItems: IProduct[]` - массив, хранящий список товаров, добавленных пользователем в корзину.

Методы класса:
`getItems(): IProduct[]` - получение массива товаров, которые в данный момент находятся в корзине.
`addItem(item: IProduct): void` - добавление товара, который был получен в параметре, в массив корзины.
`delete(id: string): void` - удаление товара, полученного в параметре из массива корзины.
`clean(): void` - очистка корзины.
`getItemsCount(): number` - получение количества товаров в корзине.
`hasItem(id: string): boolean` - проверка наличия товара в корзине по его id, полученного в параметр метода.
`getTotalPrice(): number` - получение стоимости всех товаров в корзине.

#### Класс Buyer
Необходим для хранения данных покупателя, который тот указал для оформления покупки, и реализации функционала, связанного с этими действиями.

Конструктор:
`constructor(protected events: IEvents)` — принимает объект Брокера событий для уведомления Презентера об изменениях в данных.

Поля класса:  
`private buyerData: IBuyer` - объект, хранящий текущие персональные данные и параметры заказа покупателя.

Методы класса:
`getBuyerData(): IBuyer` - возвращает объект со всеми текущими данными покупателя.  
`clearBuyerData(): void` - полностью сбрасывает данные покупателя и ошибки, возвращая их к исходному пустому состоянию.  
`validate(): Partial<Record<keyof IBuyer, string>>` - выполняет комплексную проверку заполнения полей. Проверяет тип оплаты, адрес, электронную почту и телефон.


### Слой коммуникации 

#### Класс AppApi 
Использует композицию и инкапсулирует в себе объект базового класса `Api` для взаимодействия с внешним сервером «Веб-ларёк» (получение каталога товаров и отправка оформленных заказов).

Конструктор класса принимает готовый объект, реализующий интерфейс `IApi`.

Поля класса:
`private api: IApi` - объект для выполнения HTTP-запросов (GET и POST).

Методы класса:
`getProducts(): Promise<IProductResponse>` - выполняет GET-запрос на эндпоинт `/product/`. Возвращает промис с объектом, содержащим массив товаров и их общее количество.
`createOrder(order: IOrderRequest): Promise<IOrderResponse>` - выполняет POST-запрос на эндпоинт `/order/`, передавая в теле запроса данные покупателя, список ID купленных товаров и итоговую сумму. Возвращает промис с подтверждением успешной покупки (ID заказа и сумма).


### Представление

#### Интерфейс IHeader
Содержит в себе счётчик товаров в корзине. Передаётся дженериком в класс Component.

#### Интерфейс IGallery
Содержит в себе массив карточек товаров.

#### Интерфейс IModalData
Содержит в себе разметку дефолтного модального окна.

#### Интерфейс ICard
Содержит общие данные карточек в разной реализации.

#### Интерфейс ICardActions
Колбэк-функция, вызываемая при клике пользователя.


### Список событий Представления
Описаны события, которые генерируются компонентами Представления при взаимодействии с пользователем и передаются через Брокер Событий (`IEvents`) для обработки в Презентер.

`card:select` | `CatalogCard` — генерируется компонентом карточки при клике на неё в галерее. Сигнализирует Презентеру о необходимости открыть модальное окно детального просмотра (`PreviewCard`).
`card:toBasket` | `PreviewCard` — генерируется компонентом превью при нажатии кнопки «В корзину»/«Купить». Инициирует добавление товара в Модель корзины.
`card:remove` | `BasketCard` — генерируется кнопкой-крестиком (удаления) в карточке списка корзины. Инициирует удаление товара из Модели корзины.
`basket:open` | `Header` — генерируется при клике на иконку корзины в шапке сайта. Даёт сигнал Презентеру открыть модальное окно со списком покупок.
`basket:order` | `ModalBasket` — генерируется компонентом корзины при нажатии на кнопку «Оформить». Дает сигнал Презентеру на открытие первого шага формы заказа (`OrderForm`).
`order.payment:change` | `OrderForm` — генерируется кнопками выбора оплаты. Передает в Презентер выбранный тип ('card' или 'cash').
`order.address:change` | `OrderForm` — генерируется при вводе символов в поле адреса. Передает Презентеру новое значение для валидации.
`contacts.email:change` | `ContactsForm` — генерируется при вводе email. Передает Презентеру значение для валидации в Модели.
`contacts.phone:change` | `ContactsForm` — генерируется при вводе телефона. Передает Презентеру значение для валидации в Модели.
`order:submit` | `OrderForm` — генерируется при сабмите первой формы. Сигнализирует о переходе ко второму шагу заказа (Контакты).
`contacts:submit` | `ContactsForm` — генерируется при сабмите второй формы. Сигнализирует о необходимости отправить итоговый заказ на сервер.
`success:close` | `SuccessOrder` — генерируется кнопкой закрытия окна успешной оплаты. Сигнализирует о завершении сценария и необходимости очистить корзину.


#### Класс Header 
Отображает на страницу кнопку корзины и счётчик товаров, реагирует на клик пользователя, давая сигнал о нажатии.

Конструктор:
`constructor(protected events: IEvents, container: HTMLElement)` - принимает защищенные данные обработчика и контейнер для DOM-элемента.

Поля класса:
`protected basketButton: HTMLButtonElement` - получение DOM-элемента кнопки корзины в защищенное поле.
`protected counterElement: HTMLElement` - получение DOM-элемента отображения счётчика товаров в защищенное поле.

Методы класса:
`set counter(value: number)` - принимает данные о количестве товаров в корзине, переводя их в строку.

#### Класс Gallery
Отвечает за отображение динамического списка (галереи) карточек товаров на главной странице приложения. Наследуется от базового класса `Component`.

Конструктор:
`constructor(container: HTMLElement, protected events: IEvents)` — принимает корневой DOM-элемент главной страницы (тег `<main class="gallery">`) и объект брокера событий для коммуникации с Презентером.

Поля класса:
`protected catalogElement: HTMLElement` — DOM-элемент контейнера, внутрь которого будут динамически вставляться карточки товаров.

Методы класса (Сеттеры):
`set catalog(items: HTMLElement[])` — принимает массив готовых, предварительно отрендеренных DOM-элементов карточек товаров (`CatalogCard`). Очищает текущее содержимое галереи и мгновенно вставляет новые элементы на страницу, используя метод `replaceChildren`.

#### Класс Modal
Универсальный компонент. Выполняет роль модального окна-оболочки (контейнера). Он инкапсулирует в себе общую логику открытия и закрытия окон, управления оверлеем и кнопкой-крестиком. Класс спроектирован как универсальное «приёмное гнездо», внутрь которого Презентер может динамически встраивать любые другие самостоятельные компоненты Представления (корзину, превью карточки, формы заказа). Наследуется от базового класса `Component`. Не имеет дочерних классов (закрыт от наследования).

Конструктор:
`constructor(container: HTMLElement, protected events: IEvents)` — принимает корневой DOM-элемент модального окна страницы (тег с `#modal-container`) и объект глобального Брокера событий. Вешает слушатели кликов на кнопку закрытия (крестик) и на оверлей (затемненную область вне контента) для автоматического закрытия окна.

Поля класса:
`protected closeButton: HTMLButtonElement` — DOM-элемент кнопки закрытия окна (крестик с классом `.modal__close`).
`protected contentElement: HTMLElement` — DOM-элемент контентной области (окно-контейнер с классом `.modal__content`), куда динамически внедряется разметка.

Методы класса (Сеттеры и функции):
`set content(value: HTMLElement)` — динамически подменяет содержимое модального окна. Очищает старую разметку и вставляет переданный HTML-элемент внутрь `contentElement`, используя метод `replaceChildren`.
`open(): void` — открывает модальное окно путем добавления CSS-модификатора активности `modal_active`. Генерирует событие `modal:open` в Брокер событий (для возможности блокировки скролла основной страницы).
`close(): void` — закрывает модальное окно путем удаления CSS-модификатора `modal_active`. Генерирует событие `modal:close` в Брокер событий.

#### Класс Card
Основной класс. Отображает общую реализацию карточки товара.

`constructor(container: HTMLElement, protected actions?: ICardActions)` - принимает контейнер (DOM-элемент карточки) и опциональный объект с обработчиками событий.

Поля класса:
`protected title: HTMLElement` - получение DOM-элемента названия товара.
`protected price: HTMLElement` - получение DOM-элемента отображения ценности товара.

Методы класса:
`set titleCard(value: string)` - установка названия товара.
`set priceCard(value: number | null)` - установка значения ценности через проверку типизации.

#### Класс CatalogCard
Дочерний класс `Card`. Отображает реализацию карточки товара в галереи на главной странице, используя шаблон.

Конструктор:
`constructor(container: HTMLElement, protected actions?: ICardActions)` - принимает контейнер (DOM-элемент карточки) и опциональный объект с обработчиками событий.

Поля класса:
`protected image: HTMLImageElement` — получение DOM-элемента картинки товара.
`protected category: HTMLElement` — получение DOM-элемента категории товара.

Методы:
`set image(value: string)` — устанавливает ссылку на картинку.
`set category(value: string)` — устанавливает категорию.
`categoryClass(className: string)` - отображает разный цвет в зависимости от категории.

#### Класс BasketCard
Дочерний класс `Card`. Отвечает за отображение карточки товара внутри списка в модальном окне корзины.

Конструктор:
`constructor(container: HTMLElement, protected actions?: ICardActions)` - принимает контейнер (DOM-элемент карточки) и опциональный объект с обработчиками событий.

Поля класса:
`protected indexCardElement: HTMLElement` — DOM-элемент для отображения порядкового номера товара в списке.
`protected deleteCardButton: HTMLButtonElement` — DOM-элемент кнопки удаления товара из корзины.

Методы класса:

### Презентер
Слой управления в приложении реализован в основном скрипте `main.ts`, который выступает в роли главного Презентера (оркестратора) страницы.

Сервисы и Модели данных (Бизнес-логика):
`productsModel` (`Products`) — модель для хранения и получения каталога товаров.
`basketModel` (`Basket`) — модель управления состоянием корзины (добавление, удаление, расчёт суммы).
`buyerModel` (`Buyer`) — модель хранения персональных данных и выполнения бизнес-валидации полей.
`appApi` (`AppApi`) — сетевой клиент для работы с API бэкенда (получение товаров, создание заказа).

Глобальные компоненты страницы:
`headerView` (`Header`) — отвечает за верхнюю панель сайта и вывод счётчика товаров.
`galleryView` (`Gallery`) — контейнер для сетки товаров на главной странице.
`modalView` (`Modal`) — универсальное модальное окно-оболочка (управляет оверлеем и крестиком).

Динамические компоненты модального окна:
Инициализируются один раз при старте приложения путём передачи разметки из функции `cloneTemplate`:
`previewCardView` (`PreviewCard`) — карточка детального просмотра товара.
`basketView` (`ModalBasket`) — интерфейс списка товаров и итоговой стоимости в корзине.
`orderFormView` (`OrderForm`) — форма первого шага заказа (выбор оплаты и ввод адреса).
`contactsFormView` (`ContactsForm`) — форма второго шага заказа (ввод Email и телефона).
`successOrderView` (`SuccessOrder`) — окно подтверждения успешной оплаты заказа.

#### Цепочки обработчиков событий

Каталог и детальный просмотр товара:
`events.on('catalog:changed')` — ловит сигнал об обновлении каталога от `productsModel`. Маппит массив объектов товаров в HTML-карточки `CatalogCard` и передаёт их в сеттер `galleryView.catalog`.
`events.on('card:select')` — ловит клик по карточке в галерее и фиксирует выбранный товар в `productsModel`.
`events.on<...Context>('card:selected')` — срабатывает при фиксации товара в модели. Заполняет сеттеры `previewCardView` данными, актуализирует текст кнопки покупки и открывает окно через `modalView.open()`.

Управление корзиной:
`events.on('card:toBasket')` — ловит нажатие кнопки покупки в превью. Добавляет товар в `basketModel` или удаляет его, если он там уже находился.
`events.on('basket:changed')` — реагирует на любые изменения в модели корзины. Синхронно обновляет счётчик `headerView.counter`, перерисовывает список `BasketCard` в `basketView.items`, актуализирует итоговую стоимость, валидирует кнопку «Оформить» и переключает текст кнопки в открытом превью.
`events.on('card:remove')` — ловит клик по иконке удаления (урне) в списке корзины и инициирует метод `basketModel.delete()`.
`events.on('basket:open')` — ловит клик по иконке корзины в шапке (привязан через прямой `addEventListener` в `main.ts`). Актуализирует данные корзины и выводит её на экран через `modalView.content`.

Оформление заказа и валидация «по клику»:
`events.on('basket:order')` — ловит клик на кнопку «Оформить». Сбрасывает данные в модели покупателя и открывает пустую форму `orderFormView` (кнопка «Далее» изначально активна для проверки).
`events.on('order.payment:change')` — ловит переключение кнопок оплаты. Записывает способ в `buyerModel` и мгновенно подсвечивает активную кнопку через сеттер `orderFormView.payment`.
`events.on('order.address:change')` / `events.on('contacts.*:change')` — точечно транслируют вводимый пользователем текст из инпутов в метод `buyerModel.setOrderField()`.
`events.on('order:submit')` — срабатывает при нажатии на кнопку «Далее». Запрашивает валидацию у `buyerModel`. Если есть ошибки первого шага (оплата/адрес) — блокирует переход и выводит их на экран. Если ошибок нет — переключает контент модалки на ввод контактов `contactsFormView`.
`events.on('contacts:submit')` — срабатывает при нажатии на кнопку «Оплатить». Проверяет инпуты email и телефона. При наличии ошибок выводит их в форму. Если данные валидны — агрегирует финальный объект `IOrderRequest` и отправляет POST-запрос через `appApi.createOrder()`. При успехе выводит окно `successOrderView` со списанной суммой.
`events.on('success:close')` — закрывает окно успеха, сбрасывает данные покупателя и полностью очищает корзину через `basketModel.clean()`, возвращая пользователя к исходному состоянию главной страницы.
